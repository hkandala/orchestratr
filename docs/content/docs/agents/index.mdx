orchestratr drives four kinds of agent. the core names none of them. everything that differs
between them is in the table below, plus the integration code for each kind.

**the table is the specification.** each agent page holds the evidence behind its column, the
traps, and what was not verified. where a page and the table disagree, the page's evidence wins,
and the table is fixed.

### herdr integration

every kind needs its herdr integration, which herdr installs with `herdr integration install
<kind>`. herdr recognizes an agent by its process name, so each kind must run under its usual
name.

## the kind entry

the core reads one entry per kind and nothing else. a new kind fills in these fields. the rest of
the table above is notes for the integration's author, which the core never reads.

| field | what it is |
|---|---|
| `kind` | the kind value, also herdr's integration name and the process name herdr detects |
| `binary` | the default program name, overridden by `kind.<k>.binary` |
| `versions` | the supported range, and how to read the version from `<binary> --version`. where a kind has two lines (OpenCode), the entry says which line a version belongs to, and orchestratr records it as `kind_version`. |
| `home` | the variable that `kind.<k>.home` sets, or none |
| `session_vars` | the [session variables](/docs/how-it-works#session-variables) to remove at launch. the tuios list is a core constant, not a kind's. |
| `integration` | the version, and the embedded files, if any. a kind with no files names its bridge, built into the binary and run as `orcr bridge <kind>`. |
| `send_tool` | the send tool's name as the model sees it (`mcp__orcr__send`, `orcr_send`). the server puts it in the reply hint of the message's `model_text`. |
| `checks` | the kind's install and start checks |
| `prepare(cwd)` | settings written before launch. only Claude Code has one: the trust key. |
| `launch(agent, folder)` | the arguments and variables for the [launch line](/docs/how-it-works#the-launch-line), including how the integration is loaded and how `model` and `effort` are passed. it may refuse a combination, as OpenCode refuses an effort with no model. |
| `read(record)` | the transcript reader, from the session in the record. it returns the shape in [transcripts](/docs/how-it-works#transcripts). |
| `models()` | the catalogue probe |

that is the whole per-kind surface of the core. delivery, readiness and state need no per-kind
code in the core: the integration and herdr provide them.

## behavior every kind shares

- **a steer reaches the model at the next tool call.** if the turn makes no further tool call,
  it runs as the next turn. each kind's own screen names this differently: queued message,
  steering, or messages to be submitted after the next tool call.
- **an injected message shows in the agent's own interface**, in the agent's own style. a person
  watching or attached sees it arrive.
- **nothing is typed.** a person attached to the pane can type at the same time, and their input
  and the agent messages interleave in the agent's own queue.

known limits for each kind are collected in [limitations](/docs/limitations#per-kind).
