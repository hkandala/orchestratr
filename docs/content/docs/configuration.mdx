## file

```text
~/.config/orcr/config.toml
```

the file is optional. orchestratr works with no configuration at all.

## keys

```toml
[orcr]
socket = "~/.local/state/orcr/orcr.sock"

[kind.claude]
binary = "claude"
home   = "~/.claude"
model  = "sonnet"
effort = "high"
args   = []

[kind.codex]
binary = "codex"
home   = "~/.codex"
args   = ["--search"]

[kind.pi]
binary = "pi"
home   = "~/.pi"

[kind.opencode]
binary = "opencode"
home   = "~/.config/opencode"
```

| key | default | purpose |
|---|---|---|
| `orcr.socket` | see below | where the server listens. |
| `kind.<k>.binary` | the kind's own name | which program to run. use this to test a build. see [`binary`](#binary). |
| `kind.<k>.home` | the kind's own default | the configuration directory orchestratr reads and writes for that kind. see [`home`](#home). |
| `kind.<k>.model` | the kind's own default | used when `--model` is not given. |
| `kind.<k>.effort` | the kind's own default | used when `--effort` is not given. |
| `kind.<k>.args` | empty | extra arguments, appended after the arguments orchestratr builds. |

the default socket path is `$XDG_RUNTIME_DIR/orcr/orcr.sock`, or
`~/.local/state/orcr/orcr.sock` when `XDG_RUNTIME_DIR` is not set.

## precedence

a command line flag beats the configuration file, and the configuration file beats the kind's
own default.

`args` is the exception: it is always appended. it does not replace what orchestratr builds,
because orchestratr must control the permission bypass argument and the startup arguments.

## `binary`

this key exists because the name of a program does not always identify the program.

[`orcr doctor`](/docs/cli#orcr-doctor) reports the resolved path and the reported version of
each kind's binary.

## `home`

orchestratr reads each kind's configuration directory, and writes to only one of them: three
keys in Claude Code's, for the folder trust record, the theme picker and the security notes
screen. Codex, Pi and OpenCode carry their startup settings as launch arguments or inline
configuration, so orchestratr writes nothing for them. see
[startup screens](/docs/readiness-and-delivery#startup-screens) and
[configuration writes](/docs/limitations#configuration-writes).

point `home` at a directory under a temporary path to run agents with a configuration separate
from the person's own.

<Callout type="warn" title="a fresh directory shows every startup screen">
  if the directory is fresh, some kinds show every startup screen, and orchestratr must then
  suppress each screen, key by key.
</Callout>

## not configurable

these are deliberately fixed.

| not configurable | why |
|---|---|
| permission bypass | orchestratr bypasses permissions on every agent it starts. a setting would create a mode that nothing else in orchestratr accounts for. |
| the backend | herdr is required. |
| the backend session name | it is always `orcr`. a name that varies makes reconciliation ambiguous for no gain. |
| delivery timeouts | they are derived from measurements per kind, recorded on the [agent pages](/docs/agents). a guessed value is worse than a measured one. |
| polling intervals | same reason. |
| the readiness signal per kind | it is a property of the agent, not a preference. |
| state names | a shared vocabulary that can be renamed is not shared. |

## environment

orchestratr reads no environment variable for its own settings.

orchestratr removes known child session markers from the environment it passes to the herdr
server. one of them silently disables transcript writing for a kind, and orchestratr confirms
message delivery by reading transcripts. see [Claude Code environment](/docs/agents/claude#environment).

orchestratr preserves every variable the herdr integrations require. removing them stops the
integrations from reporting, which stops session binding.
