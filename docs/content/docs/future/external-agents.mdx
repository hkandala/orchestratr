title: "external agents"
description: "reading and driving agents that orchestratr did not start"
---

## what orchestratr does now

orchestratr controls only the agents it started (see [scope](/docs/purpose#scope)). an agent
that a person started in their own terminal, or that another tool started, is invisible to
orchestratr.

## what people would want

two things. one is easy and one is not.

### reading

show the conversations of agents that orchestratr did not start: list them, read their
transcripts, and report their state.

this is close to free. transcript reading is already backend independent, and orchestratr
already converts four transcript formats into one shape (see
[transcripts](/docs/implementation#transcripts)). what is missing is discovery: finding
transcripts on disk without a record of having created them, and deciding which working
directory each one belongs to.

<Callout type="warn" title="never derive a working directory from a transcript path">
this rule must survive that work. every kind mangles the directory into its transcript path,
and the mangling is lossy. two different directories can produce the same path segment.
</Callout>

### driving

send messages to an agent that orchestratr did not start, interrupt it, or stop it.

this is not close to free, and it is where the risk is.

## why driving an external agent is different

an agent that orchestratr started has known properties:

- orchestratr chose its flags, so it knows permissions are bypassed.
- orchestratr cleared its startup screens, so it knows the agent reached a usable state.
- orchestratr placed it in a pane that orchestratr owns.

none of that holds for an external agent. it can wait on a permission prompt that
orchestratr's launch flags would have removed. it can be in a mode orchestratr does not
recognize. typing into it can answer a question that a person was about to answer differently.

the failure is silent. a dialog consumes a message sent into it, the enter key answers the
dialog, and nothing reports an error.

## what must be decided first

- whether reading ships separately from driving. it should.
- how an external agent is discovered, and how orchestratr decides which backend pane, if any,
  it occupies.
- whether orchestratr refuses to drive an external agent by default, and what makes it willing.
- what [`orcr agent list`](/docs/cli#orcr-agent-list) shows, and how a caller tells the two
  populations apart. that needs a field, and the field should be a property of the agent rather
  than a separate command.
