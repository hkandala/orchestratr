## the interface

```sh
codex app-server
```

JSON-RPC over standard input and output. the handshake is `initialize`, then `initialized`, then
ordinary method calls.

some methods require the controlling program to declare `capabilities.experimentalApi: true`
during `initialize`. without it, they are rejected.

## process shape

verified: `codex app-server` is a plain subprocess, not a daemon. closing its standard input ends
it, and it takes its whole process tree with it. there is no port and nothing to clean up.

a separate daemon does exist, behind explicit subcommands. a supervisor that never calls those
subcommands never creates one.

## state

Codex reports turn state as typed events, including a variant for waiting on approval and a
variant for waiting on user input. that is the structured form of `blocked`, which the
interactive mode can only infer from the screen.

## model catalogue

`model/list` returns the models and, for each, its supported effort values with a description
string. [Codex model catalogue](/docs/agents/codex#model-catalogue) records why orchestratr reads
the same data from `codex debug models` instead.

## transcript

Codex writes a rollout file:

```text
~/.codex/sessions/<year>/<month>/<day>/rollout-<timestamp>-<uuid>.jsonl
```
