## the interface

```sh
pi --mode rpc
```

a newline-delimited JSON duplex stream on standard input and output. one process serves one
session.

requests look like `{"id":"1","type":"get_available_models"}`. the `type` field names the
operation.

## model and effort catalogue

two calls are useful:

- `get_available_models` returns the catalogue, with cost, context window, provider, and a
  `reasoning` flag per model.
- `get_available_thinking_levels` returns the effort values for the model the process was
  started with.

the second is per process, not per request. verified: with 30 models that is 30 spawns, each
about two seconds. [Pi model catalogue](/docs/agents/pi#model-catalogue) explains why, and how
`thinkingLevelMap` resolves.

## state

Pi has the strongest state reporting of the four kinds even in interactive mode, because the
herdr integration for Pi pushes full lifecycle state and screen reading is skipped entirely. a headless
Pi agent can report the same state through the RPC stream.

## transcript

Pi writes a JSONL session file under `~/.pi/agent/sessions/<mangled-cwd>/`. its herdr integration
reports the session as a path rather than an id, so the transcript location is known from the
moment the agent starts. Pi is the only kind where that is true.

## not verified

- whether `--no-session` changes what is written to disk.
