orchestratr runs AI coding agents and controls them through one interface. it supports four
kinds of agent: Claude Code, Codex, Pi and OpenCode.

each agent runs as an interactive terminal program in a pane that [herdr](https://herdr.dev)
manages. orchestratr gives each agent an identity, tracks its state, and offers one set of
commands that behaves the same way for all four kinds.

<Callout title="orchestratr and orcr">
  orchestratr is the product. `orcr` is its command line tool, and the name it uses for its
  own files, socket and herdr session. these documents say orchestratr when they mean the
  product and `orcr` only in commands and literal names.
</Callout>

## terms

| term | meaning |
|---|---|
| kind | one of the four agent programs: `claude`, `codex`, `pi` or `opencode`. |
| agent | one running session of a kind, started by orchestratr. |
| backend | herdr, the terminal backend that hosts every agent in a pane. |
| integration | the herdr integration for a kind. it reports to herdr, and herdr binds the agent's session from those reports. |
| composer | the agent's input box, where a message is typed before it is submitted. |
| turn | the work an agent does in response to a message. a message sent while a turn runs is sent mid turn. |
| delivery record | the entry an agent writes for a message it received. orchestratr reads it to confirm delivery. |
| readiness signal | a per-kind signal that appears only after every startup screen is cleared. |

## measurements

every latency, path and key in these documents comes from a live run on macOS against Claude
Code 2.1.276, Codex 0.154.0, Pi 0.85.1, and OpenCode 1.18.31 built from source. the run drove
all four through herdr 0.9.1 at protocol 22.

where something was not tested, the page says so in a section named "not verified". those
sections are part of the specification. do not implement around them silently.
