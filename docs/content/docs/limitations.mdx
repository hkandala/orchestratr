everything here is a known limit of the design, not a defect to fix during implementation. each
entry states the limit and, where there is one, what a caller can do. the evidence is on the
linked page.

## scope

**orchestratr controls only the agents it started.** an agent started by a person, or by another
tool, is not on the bus and does not appear in `orcr agent list`. see
[future work](/docs/future#peoples-own-sessions-on-the-bus).

**permissions are bypassed on every agent.** an agent can run any command in its working
directory without asking. there is no command to approve or reject a single action, and no
setting that turns this off. start agents in directories where that is acceptable.

**orchestratr removes what can stall an agent, but not everything.** it turns off each kind's
question tools, prevents its startup screens, and sets an environment that stops programs inside
shell commands from waiting for input. the tool denial was verified on Codex and OpenCode, and on
Claude Code in its `--disallowedTools` form. Pi has no such tools. these can still stop an agent,
and none can be turned off:

- a usage limit or quota dialog.
- an authentication or sign-in flow when a token expires.
- a dialog raised by an MCP server, including its consent flows.
- a model migration or upgrade notice.
- a dialog from one of the person's own extensions, on Pi.

a stalled agent reads `blocked`. orchestratr cannot clear it: attach with
[`orcr agent attach`](/docs/cli#orcr-agent-attach) and answer it. messages sent meanwhile wait in
the agent's queue, and nothing typed reaches the dialog.

**herdr is required**, with its integration for each kind. so is the orcr integration for each
kind orchestratr drives.

## integrations

**each integration depends on an extension system that is young and changes.** Claude Code's
mods arrived in 2.1.287 and grow every week. Codex's app-server is marked experimental. OpenCode
1.x and 2.x have different plugin interfaces. orchestratr's answers:

- each integration declares a version range;
- its tests run at the minimum version and at the newest;
- `agent new` fails closed when an integration does not register.

these extension interfaces are still more stable than the terminal screen, which the earlier
design typed into.

**an integration can be switched off by the person's environment.** examples:

- Claude Code loads no mod under the conditions listed in [checks](/docs/integrations#checks).
  some company-managed sensitive modes set one of them. Anthropic can also turn mods off
  remotely.
- OpenCode loads no plugin under `--pure`.

`orcr integration status --check` reports what it can detect. the rest shows as
`integration_missing` with reason `not_registered` at the first start.

**the integration runs inside the person's agent.** a bug in it is a bug in their session. the
[contract](/docs/integrations#the-contract) keeps each one small, catches every error, and loads
it only for agents orchestratr starts.

## messaging

**delivery is at least once.** a reload of the integration between `.accepted` and `.delivered`
can deliver the message again. each kind's page says how its integration narrows this.

**`.delivered` means the model has the message, not that it acted on it.** a provider error or an
expired login can end the turn without an answer. a watch then ends `idle` with the last text,
or the caller sees no reply.

**do not send a message again after `pending` or `queued`.** see
[outcomes](/docs/messaging#outcomes).

**an interrupt can cancel accepted steers.** on Pi and on Codex, an abort, including the person
pressing Esc, silently drops steers the agent had accepted and not yet delivered. on Codex, a
steer already delivered is not answered either: it stays in history, and a later turn may or may
not act on it. the integration hands them over again after the interrupted turn (see
[the contract](/docs/integrations#the-contract), item 7). they arrive one turn later than they
would have. on Codex, a steer that was already delivered then appears twice in the agent's
history.

**a steer may wait for the running tool call.** a message sent while an agent runs a 60-second
command reaches the model when the command returns. it reads `queued` until then. Codex's
code-mode models, the default on 0.163, take a steer within about a second, even during a
command.

**messages from different senders are ordered by send time to the millisecond**, not by a shared
sequence.

**the bus has no access control beyond file permissions.** see
[what the bus does not do](/docs/messaging#what-the-bus-does-not-do).

## per kind

### Claude Code

- **mods run only after workspace trust.** orchestratr writes the trust key before launch, so
  the record cannot appear while the trust dialog is up. an untrusted folder shows as
  `not_registered`.
- **mods ignore `/clear` and `/resume` as session starts.** the session id changes with no event,
  so the integration looks it up again when a turn starts.
- **subagents fire the same events as the main agent.** the integration ignores events that carry
  an agent id. a steer can never land inside a subagent.
- **an abort leaves a running shell command in the background.** it may later produce a
  notification turn.
- **orchestratr writes one key into `.claude.json`** in the Claude Code configuration folder, the
  folder trust for the working
  directory, under Claude Code's own lock. see
  [writing a person's configuration](/docs/how-it-works#writing-a-persons-configuration).
- **permission bypass fails under root.** Claude Code refuses `--dangerously-skip-permissions`
  with user id zero. do not run orchestratr as root.
- **a subagent's work is not in `orcr agent read`.** Claude Code writes it to a separate file
  beside the main transcript, and orchestratr reads the main transcript only.

### Codex

- **each agent runs three processes**: the app-server, the bridge and the TUI. they share one
  process group and die together with the pane.
- **thread configuration goes on the app-server.** a `--remote` TUI forwards only a short list of
  `-c` keys, so trust, tools, effort and the MCP server must be passed to the app-server. so must
  `kind.codex.args`.
- **`--remote` refuses** `--add-dir`, `--worktree`, extra writable roots and `/cd`.
- **an interrupt does not stop a running shell command.** that needs the agent's own stop
  command, typed by a person.
- **the app-server socket has no authentication beyond file modes.** see
  [Codex traps](/docs/agents/codex#traps).
- **a hooks file in the Codex home shows a review screen.** herdr's Codex integration is such a
  hook. `orcr doctor` reports an untrusted herdr integration.

### Pi

- **Pi's own built-in pickers are not reported as blocked.** `/model`, `/resume` and `/tree` do not
  go through the extension dialog events. extension dialogs are reported.
- **the process must be named `pi`.** herdr does not recognize `pi.real`.
- **an authentication failure leaves the message undelivered.** Pi reports the error to its screen
  only, so the sender sees `queued` or `pending` with no reason. see
  [not verified](/docs/agents/pi#not-verified).
- **a non-blocking `ctx.ui.custom()` overlay reads `blocked`**, so a watch can end `blocked`, and
  `--reply` exit 4, while the agent works.
- **pi-herd sees orchestratr's Pi agents.** pi-herd registers every Pi session in herdr, so they
  appear on its dashboard. the two sets of tools do not clash.
- **the effort values need one probe per model.** [`orcr models`](/docs/cli#orcr-models) reports
  them only with `--model`.

### OpenCode

- **two lines, one integration.** 1.x and 2.x have different plugin interfaces, launch flags,
  transcripts and catalogues. the integration covers both, and orchestratr records the line each
  agent runs.
- **2.x must run `--standalone`.** without it, the TUI joins a shared service, which ignores the
  agent's environment and its plugin. each agent therefore has its own server process, about
  330 MB in one measurement.
- **a 2.x agent killed mid turn can be resumed later, unattended.** 2.x keeps an interrupted turn
  marked as running unless a user interrupt clears it, and its shared service resumes such turns
  at boot. `orcr agent stop` interrupts first. a crash cannot.
- **do not open an orchestratr session in your own OpenCode.** two processes would execute one
  session.
- **1.x has no idle rule in herdr**, so its idle is a default rather than an observation. a watch
  on a 1.x agent can end `idle` early.
- **1.x does not tell the plugin which session the TUI shows.** the integration's TUI half
  reports it.

## reported upstream

these are better fixed upstream than worked around here:

1. **herdr:**
   - map Pi's dialog events to `blocked` in herdr's own Pi integration.
   - recognize `pi.real`.
   - make `pane.process_info` with `target` answer for the target.
   - add positive idle rules for the kinds that have none.
   - drive Claude Code and Codex state from hooks, not only the screen: `UserPromptSubmit`,
     `Stop`, `PermissionRequest`, `Notification` and `SessionEnd`, and `Interrupt` on Codex.
     herdr's hook now handles `SessionStart` only. corgi, another agent tool, shows that the same
     entry point carries them.
   - read `background_tasks` from Claude Code's `Stop` payload, so an agent that a background
     shell or subagent will wake is not reported as plain idle.
2. **Claude Code:**
   - a steer option for `$.prompt.submit`.
   - an event after `/clear` and `/resume` that carries the new session id.
   - a file watch in the mod API.
3. **Codex:**
   - a stable app-server protocol.
   - fix: queued input stays stuck after an interrupt.
   - fix: an interrupt drops another client's pending steer, and leaves a written one unanswered.
   - let a hook or MCP server enqueue input.
4. **Pi:**
   - keep or report custom messages when an abort clears the queues.
   - report a failed `sendMessage`.
   - a duplicate tool name should be a diagnostic, not an exit.
5. **OpenCode 2.x:**
   - an owner on a turn's running mark, so a shared service never resumes another process's turn.
   - per-client plugins and environment on the shared service.

## not verified

the gaps that touch more than one kind. the gaps specific to one kind are on its page.

- two agents of one kind in one working directory, each receiving only its own messages.
- delivery while the recipient is compacting its conversation.
- a message of 32 KB, and messages with many lines, on every kind.
- herdr restarting while agents run: whether each kind's restored pane is detected as `exited`,
  and whether a relaunched agent's integration stays inert.
