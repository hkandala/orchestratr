the socket API is the product. the [`orcr` command line tool](/docs/cli), the agents'
[tools](/docs/integrations#tools) and any future client, such as a web interface, are all callers
of it. every command maps to one method.

## the server

the server is the one long-lived orchestratr process. it does four things that must happen in
one place:

- it answers requests from every client;
- it runs the [watches](/docs/messaging#watches);
- it pushes [events](#events) to subscribed clients;
- it deletes integration folders that nothing uses.

it keeps no state of its own that cannot be rebuilt. agents, messages and markers are files on
the [bus](/docs/messaging#the-bus), and agent state comes from herdr. it follows state with
herdr's own `events.subscribe`, one subscription per agent pane, and reads a fresh snapshot
whenever that connection drops.

**starting.** any client starts the server when it is not running, under a lock on the socket
folder, so two clients never start two servers. the server holds `bus/.server.lock` for its whole
life, so a second server on the same bus refuses to start. the client starts it detached: in a
new process session, with no terminal, and with the client's environment minus every kind's
[session markers](/docs/how-it-works#session-markers) and every `HERDR_*` and `ORCR_*` variable. a
server started by a tool inside an agent must not die with that agent's pane, and must not act in
that agent's herdr session.

**upgrading.** a client that finds an **older** server asks it to exit with
[`server.exit`](#methods), and starts its own. a client that finds a newer or equal server uses
it, as long as it speaks the client's `protocol`. long-lived old clients, such as an agent's
`orcr mcp` from before an upgrade, therefore never replace a newer server.

**restarting.** on start, the server reconciles:
- a record that is still `starting` after its `ready_by` time belongs to an `agent new` that a
  crash interrupted. the server stops it as `agent new` would have.
- a record whose `pid` is not running is `exited`.
- watches are found again from the bus (see [watches](/docs/messaging#watches)).

**while it is down,** integrations still deliver what is already in their inboxes. a new send
starts the server first.

## transport

the server listens on a UNIX domain stream socket at `$XDG_STATE_HOME/orcr/run/orcr.sock`, which
is `~/.local/state/orcr/run/orcr.sock` by default. the path is fixed, and does not depend on
`XDG_RUNTIME_DIR`, which differs between a desktop session and an SSH login. every client and
every agent's tools must find the same server without asking. the folder is created with mode
`0700`, because any process that can connect can start agents with permissions bypassed.

the framing is newline-delimited JSON: one compact JSON object per line, UTF-8, terminated by
`\n`. a connection carries many requests, and their responses can come in any order. a response
carries the `id` of its request.

a request frame larger than 8 MiB closes the connection. responses have no limit.

the first frame on a connection must be [`hello`](#hello).

## request

```json
{"id": "c1", "method": "agent.list", "params": {}}
```

| field | meaning |
|---|---|
| `id` | any string the client chooses. the server echoes it. |
| `method` | a method from [methods](#methods). |
| `params` | an object. `{}` when a method takes no arguments. |

## success response

```json
{"id": "c1", "ok": true, "result": {"agents": []}}
```

## error response

```json
{"id": "c1", "ok": false,
 "error": {"code": "not_ready", "message": "agent codex-1 has exited",
           "details": {"name": "codex-1", "state": "exited"}}}
```

`id` is an empty string when the server could not read the request far enough to find one.

`code` is one of eight values. the set is closed.

| code | meaning | exit code |
|---|---|---|
| `invalid_request` | the frame or the arguments are wrong. | 2 |
| `unsupported_protocol` | the client's protocol is not supported. | 6 |
| `not_found` | no agent has that name or id. | 3 |
| `not_ready` | the agent cannot do this now. `details.state` says why. | 4 |
| `timeout` | the action did not finish in time. `details.result` says what is known. | 5 |
| `backend_unavailable` | herdr is missing, stopped, or incompatible. | 6 |
| `integration_missing` | the kind's orcr integration is not usable. `details.reason` is `not_installed`, `check_failed` or `not_registered`. | 7 |
| `internal` | anything else. | 1 |

`message` is prose for a person, and says what to do next when there is something to do.
`details` carries machine-readable specifics. a small code set stays usable only if specifics go
in `details` and not into new codes.

`orcr agent attach` has no method, because it hands over a terminal.

every method that acts on an agent takes `agent`: a name or an id. every method that sends,
starts or stops takes `from`: an agent id, or `"orcr"`. an agent may stop only the agents it
started, and the agents they started. `orcr` may stop any agent. the CLI and the tools fill it in from `ORCR_AGENT_ID` (see
[the sender](/docs/cli#the-sender)).

### `hello`

```json
{"id": "c0", "method": "hello", "params": {"protocol": 1, "client": "orcr-cli", "version": "0.2.0"}}
```

```json
{"id": "c0", "ok": true, "result": {"protocol": 1, "version": "0.2.0"}}
```

a server that does not speak the client's `protocol` answers `unsupported_protocol`. a client
that sees an older `version` than its own asks the server to exit and starts a new one. see
[upgrading](#the-server).

### `agent.new`

```json
{"kind": "codex", "cwd": "/Users/me/code/p", "model": null, "effort": "high", "name": null,
 "message": null, "needs_reply": false, "wait_reply": false, "wait_ready": true,
 "timeout_ms": 120000, "from": "orcr"}
```

`kind` is required. the result is one agent object, as in
[`orcr agent new`](/docs/cli#orcr-agent-new).

- `message` is written into the inbox before launch, with `needs_reply` if set.
- `wait_ready: false` returns as soon as the agent is launched, in state `starting`. the `start`
  tool uses it. a failure to start then reaches the parent as the watch's `exited` ending.
- `wait_reply` waits for the reply, as in `message.send`.

### `agent.get`

```json
{"agent": "codex-1", "wait": ["idle", "blocked"], "timeout_ms": null}
```

`wait` null or empty returns at once.

### `agent.read`

```json
{"agent": "codex-1", "last": 50}
```

### `message.send`

```json
{"from": "orcr", "to": "codex-1", "text": "also check the tests", "delivery": "steer",
 "id": null, "reply_to": null, "needs_reply": false, "wait_reply": false, "timeout_ms": 30000}
```

- `to` is an agent, or `"orcr"`. a message to `orcr` cannot ask for a reply.
- `id` is optional, in the [message id format](/docs/messaging#messages). a client that may retry
  chooses it. a retry with the same id, sender and text writes nothing new and returns the
  current outcome. the same id with other content is refused with `invalid_request` and
  `details.reason: "id_in_use"`.
- `needs_reply` starts a watch.
- `wait_reply` also holds the response until the reply or the watch ending, and puts it in
  `reply`. it implies `needs_reply`. `timeout_ms` is then the watch's deadline.

the result is the [send result](/docs/cli#orcr-agent-message).

### `message.list`

```json
{"agent": null}
```

null lists the `orcr` inbox.

### `models.list`

```json
{"kind": null}
```

### `events.subscribe`

```json
{"agents": null}
```

the response carries a snapshot of every agent (or the named ones), then events stream on the
same connection until it closes:

```json
{"id": "c9", "ok": true, "result": {"subscription": "s1", "snapshot": {"agents": []}}}
```

there is no replay. a client that reconnects subscribes again and takes a new snapshot. messages
are files, so nothing durable lives only in the event stream.

## events

```json
{"subscription": "s1", "event": {"type": "agent.state_changed", "agent": "019fd875-…",
 "name": "codex-1", "state": "working", "at": "2026-10-06T09:22:10Z"}}
```

an event frame has no `id`, because it answers no request.

| type | when |
|---|---|
| `agent.state_changed` | an agent's state changed, including from `starting` and to `exited`. |
| `agent.removed` | `stop` removed an agent's record. |
| `message.sent` | a message file was written. carries `id`, `from` and `to`. |
| `message.accepted` | an integration wrote `.accepted`. |
| `message.delivered` | an integration wrote `.delivered`. |

## schema

the server generates its JSON Schema from the same method table it dispatches on, so the schema
cannot drift from the code. every `$ref` uses the standard root `#/$defs/`.
`orcr serve --schema` prints it.
